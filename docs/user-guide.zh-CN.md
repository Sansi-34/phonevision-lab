# 完整操作指南：从采集到硬件联动

本指南覆盖 PhoneVision Lab 的完整闭环：**采集 → 训练 → 导出 → 手机离线推理 → LED 联动 → 性能记录**。

> 数据、图片和模型默认保存在本机（`%LOCALAPPDATA%\PhoneVisionLab`）。手机推流和硬件控制需要局域网；首次使用预训练权重可能需要联网下载。

---

## 0. 环境准备

### 电脑端（Windows）

本机请从项目根目录双击 `start-training.cmd` 启动训练工作台。普通 `start.cmd`
使用轻量环境；当前 Windows 便携包不内置 TensorFlow，也尚未连接独立训练环境，
不能直接在便携包里训练或导出。

```powershell
cd pc-client

# 基础依赖（预览 / 采集 / 数据集管理）
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

# 训练依赖（可选，只有要训练模型时才需要；约 500 MB）
pip install -r requirements-train.txt
```

> 训练依赖与基础依赖是分开的：只想看画面、采数据时不必装 TensorFlow。

### Android 端

需要 JDK 17 + Android SDK：

```powershell
$env:JAVA_HOME = "C:\Program Files\Eclipse Adoptium\jdk-17.0.20+8"   # 改成你的路径
$env:ANDROID_HOME = "C:\Users\<你>\AppData\Local\Android\Sdk"
cd android
cmd /c gradlew.bat assembleDebug
```

产物：`android/app/build/outputs/apk/debug/app-debug.apk`

用数据线安装到旧手机：

```powershell
adb install -r android\app\build\outputs\apk\debug\app-debug.apk
```

## 1. 数据集与采集

1. 启动电脑客户端：`python main.py`，输入手机 IP 连接（与原有推流流程相同）。
2. 在底部标签页切到 **数据集**：
   - 点 **新建**，输入数据集名（例如 `my-objects`）。
   - 在类别输入框输入类别名（例如 `apple`），点 **新增类别**。重复添加全部类别（至少 2 个）。
   - **类别由你自己定义**，不限定具体物品；类别名会变成目录名，只能用字母、数字、`_`、`-`、`.`。
3. 采集：
   - 在"采集类别"下拉选择当前要拍的类别。
   - 设置连续采集间隔（默认 500 ms）。
   - 点 **采集一张** 拍单张；点 **开始连续采集** 持续拍，点 **停止采集** 结束。
4. 每个类别**至少拍 2 个不同批次**（拍一会儿、停一下、换个角度再拍），每次"开始连续采集"算一个新批次。

> **为什么强调多个批次**：训练/验证集按"批次"划分，同一批次的相邻近似帧绝不拆开。只有一个批次时无法划分验证集，客户端会明确提示，不会用虚高的指标糊弄你。

5. 点 **数据体检**：客户端会检查类别是否缺失、样本是否足够、图片能否解码、是否严重失衡。有问题会逐条列出。
6. 点 **划分训练/验证**：按批次切分，结果存到 `<数据集>/split.json`（含随机种子与比例，可复现）。

### 建议样本量

| 场景 | 每类样本 | 每类批次 |
| --- | --- | --- |
| 快速验证链路 | 20-30 张 | 3 个 |
| 可用效果 | 80-150 张 | 4-6 个 |
| 稳定效果 | 200+ 张 | 6+ 个 |

样本要**覆盖真实使用时的角度、光照、背景**，否则手机上一换环境就掉准确率。

## 2. 训练与导出

1. 切到 **训练与导出** 标签页。
2. 参数（默认值适用大多数情况）：

   | 参数 | 默认 | 说明 |
   | --- | --- | --- |
   | Epochs | 15 | 样本少时 10-15 足够，过多会过拟合 |
   | Batch | 16 | 内存不够就调小 |
   | Input | 224px | 旧手机建议 160-192px；224px 兼容 ImageNet 权重 |
   | Device | CPU | 检测到 GPU 才会出现 GPU 选项 |

3. 点 **开始训练**。进度、损失、验证准确率实时显示；可随时 **取消训练**。
4. 训练完成后（状态显示"训练完成"），点 **导出模型包**。
5. 导出会做**一致性校验**：用固定样本对比导出前后的输出，显示最大误差与 Top-1 一致率。

   - 误差 ≤ 0.05 且 Top-1 一致率 ≥ 98% → 通过，生成模型包。
   - 不通过 → **明确拒绝导出**，不会产出看似成功、实际跑不起来的模型包。

6. 模型包位置：`%LOCALAPPDATA%\PhoneVisionLab\runs\<run 名>\<run 名>.pvlmodel.zip`

### 模型包里有什么

| 文件 | 内容 |
| --- | --- |
| `model.tflite` | 转换后的 TFLite 模型（float16 量化） |
| `manifest.json` | 完整自描述：输入尺寸/布局/颜色顺序/归一化/输出解释/训练参数/兼容信息 |
| `labels.json` | 类别标签（索引 → 名称） |
| `consistency.json` | 导出一致性校验记录 |
| `README.txt` | 人类可读说明（含预训练权重来源与许可证） |

## 3. 手机端导入与离线推理

1. 手机安装 APK 后打开，点 **本机 AI 推理（导入模型）**。
   - 这会自动停止推流：两种模式互斥，旧手机开两路相机会直接失败。
2. 点 **导入模型包 (.pvlmodel.zip)**，用系统文件选择器选中第 2 步生成的 `.pvlmodel.zip`。
3. 导入校验（任何一项不匹配都会**明确拒绝并说明原因**，不会崩溃）：
   - 模型包格式版本
   - 必需文件齐全
   - 输入形状与预处理声明的尺寸一致
   - 颜色顺序 / 张量布局 / 归一化方式受支持
   - 预处理契约版本一致
   - 类别数 ≥ 2，且模型输出类别数与标签数一致
   - `model.tflite` 大小合理
4. 导入成功后显示：模型名、输入规格、类别列表、一致性 Top-1 一致率。
5. 点 **开始推理**。界面显示：
   - 摄像头实时预览
   - 当前模型
   - 预测类别 + 置信度
   - 推理帧率（实测）、完成帧、丢弃帧
   - 预处理 / 模型执行 / 后处理耗时（各自分开，毫秒）
   - 最近帧间隔

### 离线验证

模型导入后**断开电脑、关掉 Wi-Fi**，手机仍能独立完成摄像头推理——推理完全在本机进行，不依赖网络。

> **要分清两件事**：
> - **模型推理离线能力**：导入后不需要任何网络，本机完成。
> - **硬件通信**：手机向控制器发命令需要两者在同一局域网（Wi-Fi）。这是通信链路的需求，不是推理的需求。

## 4. 硬件联动（LED）

### 4.1 准备控制器

本项目提供 ESP32 固件：`controller-firmware/led_controller/led_controller.ino`

**接线**（按你的板子核实，不要凭空假设）：

| 部件 | 接到 |
| --- | --- |
| LED 长脚（正极） | GPIO 4（串 220Ω 限流电阻） |
| LED 短脚（负极） | GND |

**供电与电平注意**：
- 按实际开发板的数据手册确认 GPIO 电压和电流限制，**LED 必须串限流电阻**。
- 红色 LED 压降约 2V：`(3.3 - 2) / 0.01 ≈ 130Ω`，取 220Ω 更安全。
- **驱动舵机/电机绝不能直接接 GPIO**：需要独立电源与驱动板。

**上传前改两处**（固件顶部配置区）：

```cpp
#define WIFI_SSID "你的WiFi名"
#define WIFI_PASSWORD "你的WiFi密码"
```

**依赖**：Arduino IDE 装 ESP32 板包 + `ArduinoJson`（v7）。

上传后开串口监视器（115200），会打印：

```
[wifi] connected, IP = 192.168.x.x
[http] listening on port 8081
```

记住这个 IP。

### 4.2 手机端连接与手动验证

1. 手机与控制器连**同一个 Wi-Fi**。
2. 在推理界面的"硬件联动"区填入控制器 IP，点 **连接**。
   - 连接时会发一条只读查询验证链路，不动任何执行器。
3. **先手动验证**：点 **手动 LED 开** / **手动 LED 关**，确认灯真的亮/灭。
4. 事件记录区会显示每条命令的状态与往返耗时。

### 4.3 开启自动控制

1. 手动验证通过后，点 **开启自动控制（默认关）**。
2. 默认规则：识别到目标类别并连续确认 3 帧置信度 ≥ 0.75 → LED 开；目标连续 5 帧消失 → LED 关；动作后 2 秒内不重复触发。
3. 在手机端选择目标类别；规则参数目前使用默认值，手机端参数设置界面尚待实现。

**三重稳定机制**（防止模型输出波动让灯乱闪）：
- **连续确认**：单帧误识别不触发。
- **滞回**：开启用高阈值（0.75），关闭用低阈值（0.45），阈值附近抖动不翻转。
- **冷却**：一次动作后一段时间内不重复动作。

只有**状态变化**时才发命令，绝不逐帧重复发送。

### 4.4 停止控制

点 **停止控制**：规则状态复位，**不会再产生新的自动动作**（LED 保持停止前的状态）。

### 4.5 命令状态四态

界面严格区分：

| 状态 | 含义 |
| --- | --- |
| 已发送 | 手机已发出，尚未收到回应 |
| 已接收 | 控制器确认收到了 |
| 已执行 | 控制器确认已执行（仅设备能确认动作完成时） |
| 失败 | 超时或失败 |

> 设备只确认"收到了"时，界面**只显示"已接收"，不显示"执行成功"**。

### 4.6 断连与重连

- 断线期间的命令直接失败，**不缓存、不重放**：重连后不会突然执行积压的动作。
- 重复命令按 requestId 去重，设备不会重复执行。
- 只有 LED 开关这类幂等动作会有限重试；**运动类动作（舵机/电机）绝不自动重试**。
- 固件带设备端看门狗：10 分钟无命令自动关 LED，不依赖手机在断线后还能发命令。

## 5. 性能测试与导出

1. 切到 **性能分析** 标签页。
2. 设置预热秒数（默认 3）与测试时长（默认 60）。
3. 点 **开始测试**，保持场景稳定，等待结束（或手动 **停止测试**）。
4. 指标分阶段显示：

| 阶段 | 指标 |
| --- | --- |
| 采集与传输 | 手机采集帧率 / PC 接收帧率 / PC 显示帧率 / 丢帧 |
| 推理与耗时 | 手机端有即时推理显示；电脑端尚未接入手机上报，显示 `--` |
| 硬件联动 | 电脑性能报告尚未接入硬件事件，显示 `--` |

预热结束后，电脑每秒采样一次并计算采集、接收和显示帧率的平均值。没有采集到的数据在 JSON 中为 `null`，不代表测量值为零。

5. 点 **导出 CSV** / **导出摘要** / **导出 JSON**，产物在 `%LOCALAPPDATA%\PhoneVisionLab\exports\`。

### 关于功耗

- PC 客户端**不测量手机功耗**，界面上明确显示"不支持"。
- 只有设备提供真实电流/电压数据源时才显示，且区分**实测 / 估算 / 电量变化**。
- **不把电量百分比变化当成精确功率**。

### 关于延迟

- 所有本机时间间隔用**单调时钟**测量。
- **绝不直接相减手机与电脑的时间戳**：两端未同步，相减得到的"端到端延迟"没有物理意义。
- 手机侧的推理帧率与三段耗时由手机端实测后上报，PC 只记录，不自己算。

## 6. 验收流程（真机）

按顺序过一遍，每步都应有可见反馈：

1. 手机连接电脑，稳定显示摄像头画面。
2. 建立数据集，采集多个类别的图片（每类 ≥ 2 个批次）。
3. 数据体检通过 → 划分 → 电脑完成训练 → 导出模型包（一致性通过）。
4. 手机导入模型，显示真实预测结果。
5. **断开电脑和网络后仍可推理**。
6. 连接实际控制器，先手动验证 LED 亮/灭。
7. 开启自动控制，目标出现后 LED 按规则开启。
8. 目标消失后 LED 按规则关闭。
9. 短暂误识别**不**产生频繁动作。
10. 断连和重连**不**执行过期命令。
11. 停止自动控制后**不**再产生新的自动动作。
12. 导出本次电脑端已采集的传输性能记录；手机推理、硬件及功耗数据尚未接入该报告。

## 7. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 导入模型被拒 | 看提示里的具体原因（版本/尺寸/颜色顺序/归一化）。用本项目导出的模型包 |
| 手机预测明显不对 | 预处理不匹配。确认 manifest 的 preprocess 与训练一致；重新导出 |
| 推理帧率低 | 看"模型执行"耗时；降低 Input 尺寸（224 → 160） |
| 延迟越来越大 | 不正常的。本项目只保留最新帧，不该堆积；重启推理 |
| LED 频繁开关 | 调高触发置信度或连续确认次数 |
| 显示"已发送"但灯不动 | 控制器没回 ack。检查 IP/端口/同一局域网/防火墙 |
| 连不上控制器 | 固件串口打印的 IP 是否与手机同网段；端口是否 8081 |
| 训练提示缺依赖 | `pip install -r requirements-train.txt` |
| 验证准确率异常高 | 检查是否只用了 1 个批次（数据泄漏）。至少 2 个批次 |
