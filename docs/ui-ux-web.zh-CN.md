## 1. 产品定位理解

**这是一个教人学会一条技术链路的平台，不是一个后台管理系统。** PhoneVision Lab 的真实形态是一条跑在局域网里的边缘视觉流水线：旧安卓手机采集画面（MJPEG，默认 `http://<手机IP>:8080`），电脑负责实时预览、传统视觉处理、数据集、训练与导出，模型回到手机本机做 TFLite 推理，手机再把命令发给 ESP32 驱动 LED，最后电脑记录传输性能。网页版要把这条链路**讲清楚**，并让人在一个可控的实验台里**亲手改一遍**，而不是把 PC 客户端的控件平铺到浏览器里。

**判断一个页面是不是"后台管理系统"，看它的第一屏在做什么。** 后台的第一屏是"筛选器 + 表格 + 分页 + 批量操作"，回答"这台服务器现在有什么"。本站的第一屏必须回答"我现在该学什么 / 该点哪里"。因此本站没有账号、没有云端、没有设备列表、没有权限与审批、没有多租户、没有"全部设备"这种跨设备视图；数据默认在本机 `%LOCALAPPDATA%\PhoneVisionLab`，网页端唯一的持久化是 `localStorage` 里的 `pvl.progress.v1`（学习进度）。整站的交互节奏是**读一页 → 试一次 → 记一笔**：读课程、在实验台试参数、把结果记进本机进度。

**三条用户路径，对应三种完全不同的页面节奏。**

| 路径 | 用户的问题 | 页面 | 节奏要求 |
| --- | --- | --- | --- |
| **学** | "这东西到底怎么运作？" | `learn.html`、`lesson.html` | 慢。一次一屏概念，正文 68ch，插图解释知识，每课结尾告诉用户"现在你能做什么" |
| **做** | "我改一个参数会怎样？" | `lab.html`、`dataset.html`、`train.html`、`deploy.html`、`hardware.html` | 快。控件即改即见，状态永远显式，禁用必须给原因 |
| **复盘** | "刚才那一次到底跑成什么样？" | `perf.html`、`projects.html` | 稳。只呈现实测值 + 明确标注"未采集/不支持"，不做美化 |

**设计含义（这几条会反复出现在后面每一页）。** ① 每个页面都必须有"现在处于哪一步、下一步点哪里"，因为目标用户是学生、创客、AI 入门者，他们第一次接触"数据集 / epoch / 置信度"，要的不是参数自由而是方向感。② 一屏之内要能投屏路演：状态、进度、结论先给，细节（带宽、JPEG 大小、日志）折叠。③ 所有"没有真实数据、没有真实反馈"的地方，用统一的能力标记说清楚，**宁可不显示，也不填演示值**。④ 三个角色（旧手机 / 电脑 / ESP32）的边界必须在界面上可见，手机端才有的能力不允许在网页上摆一个假开关。

**诚实边界决定了大量文案的写法。** 网页原型**没有任何后端**：所有"连接""采集""训练"按钮只能做本地交互演示，并且必须在文案里说明原型不会真的连接。能力状态统一四级标记：`现有`（PC 客户端或手机 App 已实现）、`未接入`（界面显示 `--`）、`未验证`（真机链路未跑通）、`规划中`（`tag--plan`）。数字只有三种来源：**实测**（必须标口径与采样方式）、**示意**（必须带角标）、**未采集**（显示 `--`，不是 `0`）。这条规则在 §7 会展开成可执行的状态清单。

### 1.1 事实基线（所有页面共享，改任何一条都要同步改本文）

| # | 事实 | 界面含义 |
| --- | --- | --- |
| 1 | 手机通过**局域网** MJPEG 推流，默认端口 `8080`，**不是 USB** | 连接弹窗只收 IP + 端口；全站不出现 USB / 数据线入口 |
| 2 | 默认采集 `640×480`、目标 `10 FPS`、JPEG 质量 `70` | 实验台画布逻辑尺寸 640×480（4:3），指标卡显示"目标 10 fps" |
| 3 | `GET /ping` 返回 `status / device / width / height / requestedFps / actualFps / frameCount` | 连接成功后状态胶囊可展开这 6 个字段；`status != streaming` 时提示先点「开始推流」 |
| 4 | `GET /stream` 是 `multipart/x-mixed-replace`，只保留最新帧 | 断流 3 秒判"画面已中断"，延迟不累积；不显示"排队中"这类假状态 |
| 5 | ESP32 端口 `8081`，命令四态 `已发送 / 已接收 / 已执行 / 失败` | 四态用同一套色点 + 文字；LED 固件只回 `received`，界面**只能显示"已接收"** |
| 6 | 功耗**不支持**测量 | 性能页功耗卡写"不支持"，不显示任何电量百分比推导的功率 |
| 7 | 手机推理指标、硬件事件**未接入**电脑报告 | 性能页对应行显示 `--`，并注明"未采集"，`null ≠ 0` |
| 8 | 数据集至少 **2 个类别**，每类至少 **2 个批次** | 数据集页与训练页都有前置条件 checklist；只有 1 个批次时**拒绝划分**并说明原因 |
| 9 | 流程是 **数据体检 → 划分训练/验证 → 训练**，不可跳步 | 训练按钮在未划分时禁用，禁用文案写明缺哪一步 |
| 10 | 导出一致性：最大误差 **≤ 0.05** 且 Top-1 一致率 **≥ 98%** 才通过，否则拒绝导出 | 部署页显示两个阈值；不通过时不出现"已生成"字样（`docs/user-guide.zh-CN.md` §2 第 5 条原文为 98%，不是 99%） |
| 11 | 训练步数少于 5 时**拒绝导出** | 训练完成但步数不足时，导出按钮禁用并说明原因 |
| 12 | 训练默认参数：Epochs 15 / Batch 16 / Input 224px / Device CPU | 参数面板默认值直接取这四项；GPU 选项只在检测到 GPU 时出现 |
| 13 | 训练依赖与基础依赖分离，便携包**不内置 TensorFlow** | 缺依赖时显示 `requirements-train.txt` 与 `start-training.cmd`，不显示假进度 |
| 14 | 数据在本机：`%LOCALAPPDATA%\PhoneVisionLab\{datasets,runs,exports,logs}` | 页脚与项目页写真实路径，不写"云端同步" |
| 15 | 课程规模：**8 章 24 课**（`site.js` 进度总数默认 24） | 所有进度百分比按 24 计；章节锚点 `#ch1`–`#ch8` |
| 16 | 当前只做**图像分类**，不是目标检测 | 全站插图不得画检测框；文案写"分类结果"，不写"识别出几个目标" |

## 2. 视觉语言

### 2.1 参考图方向（由需求方描述）

需求方对参考图的描述是：**米白纸感底、深藏青正文、单一钴蓝强调、编辑式排版（衬线大标题 + 无衬线正文 + 细线分隔 + 大留白）、克制线性插图**。

我没有看到参考图本身，因此本文不做像素级复刻，而是把这条描述**翻译成 `styles.css` 已冻结的令牌**。翻译表如下；凡是描述与令牌冲突的地方，一律以令牌为准（令牌是唯一真源，见 `DESIGN-CONTRACT.md` §1）。

| 描述词 | 令牌落点 | 具体值 |
| --- | --- | --- |
| 米白纸感 | `--paper` / `--paper-2` / `--paper-3` | `#FBF8F2` / `#F5F1E8` / `#EFEAE0` |
| 深藏青正文 | `--ink` / `--ink-2` | `#14203A` / `#3D4759` |
| 钴蓝强调 | `--blue` + 三档派生 | `#1F4BE0` / `#1639B8` / `#122F96` |
| 编辑式排版 | `--font-serif` 大标题 + `--font-sans` 正文 + 1px `--line` 分隔 + `--s9` 区块间距 | 见 §6.2 |
| 克制插图 | 24×24 线性图标 + 双色填充示意图，无渐变无阴影 | 见 §9 |

### 2.2 值得保留的 6 条

| # | 保留什么 | 为什么 | 落地约束 |
| --- | --- | --- | --- |
| 1 | 米白底 + 深藏青字的高对比纸感 | 投影/路演时后排能读；比纯白更耐看，和"实验室记录纸"的气质一致 | 正文只用 `--ink` / `--ink-2`；纸色分三层（`paper` / `paper-2` / `paper-3`）靠底色分区，不靠阴影 |
| 2 | 衬线大标题 / 无衬线正文的编辑式分层 | 一眼分出"这是文章"还是"这是控件"；这是学习平台和后台最直观的区别 | `.display/.h1/.h2` 用 `--font-serif`；按钮、导航、表格、表单**一律** `--font-sans` |
| 3 | 单一钴蓝强调 | 每屏只有一个"该点这里"，降低初学者决策成本 | 实心 `--blue` 每屏只给 1 个主按钮；其余用 ghost / quiet |
| 4 | 1px 暖灰细线 + 大留白分层 | 结构清楚但不抢画面；避免"卡片套卡片"的厚重感 | 分隔用 `--line` / `--line-2`；层级最多两层（section + card）；阴影只允许 `--shadow-1` |
| 5 | 低饱和辅助色只做卡片底 | 三种路径 / 四类提示需要颜色区分，但不能变成"彩色仪表盘" | `--mint/--sand/--lilac/--sky` 只做背景；其文字用配对的 `*-ink`，**禁止**把辅助色用作文字或按钮底 |
| 6 | 24×24 线性图标 + 圆角纪律 | 线性图标与细线排版同语言；圆角克制才不像"消费级 App" | 图标 24×24、`stroke-width 1.6–1.8`、`stroke-linecap: round`；卡片 14px、按钮/标签胶囊、输入框 6px |

### 2.3 必须避免的 5 条

| # | 不要做 | 为什么（对本项目具体有害） | 替代做法 |
| --- | --- | --- | --- |
| 1 | 深色霓虹控制台（黑底 + 青紫辉光 + 网格背景） | 会把"学习平台"读成"黑客工具"，也会让长文正文无法阅读；深色大面积还和"纸感"参考方向冲突 | 深色只出现在两处：实验台画布 `--ink`（视频底）、代码/日志块 `--paper-2`。其余全站浅色 |
| 2 | 大圆角卡片（≥20px，尤其胶囊化整卡） | 圆角越大越"营销页"，与编辑式排版冲突；也会让 14px 的细线失去结构作用 | 卡片 `--r-lg` 14px；弹窗 14px；按钮/标签/进度条用 `--r-pill`；禁止 20px 以上圆角 |
| 3 | 渐变、发光、玻璃拟态、重阴影 | 会让"未采集 / 示意"这类诚实标记看起来像装饰，破坏可信度 | 层次靠 `--paper-2` 底 + 1px 线；只有卡片 `--shadow-1`、弹窗 `--shadow-2` |
| 4 | 后台表格流（首屏就是筛选器 + 密集表格 + 分页 + 批量选择） | 本站没有"成千上万条记录"要管；表格流会把 24 节课变成"待办工单" | 学习用章节节奏（章头 + 课程行），实验用卡片 + 单步操作；表格只用于事件日志、指标明细、导入校验这类"必须逐行核对"的场景 |
| 5 | 装饰性 3D 芯片 / AI 大脑 / 发光神经网络 | 与真实链路无关；本项目最强的视觉资产是"手机→电脑→手机→LED"这条可解释的管线 | 画管线、画通道分解、画四态时序；每张图必须能回答"这一步在干什么"（见 §9） |

### 2.4 文案与配色纪律

- **禁用词**：一键部署、智能识别、颠覆、零门槛、AI 会自动帮你、云端同步、USB 连接手机、检测框/识别框。
- **替换写法**：导出模型包 / 分类结果 / 跑通链路 / 本机推理 / 局域网直连。
- **颜色三条纪律**：① 强调色只有 `--blue`；② 辅助色只做底不做字；③ 状态**永远**是"色点 + 文字"，不允许只有颜色（`DESIGN-CONTRACT` §10）。
- **数字三条纪律**：① 实测值必须写口径（"接收帧率，电脑实测"）；② 示意值必须带角标「示意」；③ 没测到写 `--`，不写 `0`、不写 `N/A`、不写"暂无数据"这种含糊说法（统一用"未采集"）。

### 3.2 全局导航 + 页面内二级导航的规则

1. **全局导航永久只 3 项**：学习 / 实验台 / 我的项目。新增的 5 个页面**不得**进一级导航，否则一级导航会退化成"功能清单"，失去"三条路径"的语义。
2. **高亮由脚本判定**：`aria-current="page"` 由 `site.js` 依据 `<body data-page>` 自动加，禁止手写。5 个待补页面统一写 `data-page="lab"`，于是"实验台"保持高亮，具体工位由二级导航表达。
3. **二级导航只在分区内出现**，形态是 6 个工位的一行横向导航，高 48px，粘在主导航下方（`position: sticky; top: var(--nav-h)`，`z-index: 30`）。当前项：文字 `--ink` + 600 + 底部 2px `--blue` 下划线；非当前项 `--ink-3` + 550。

- 一个类别拍了 100 张、但只有 1 个批次 → 划分按钮禁用，文案必须解释**为什么**（验证集无法独立），不能只说"条件不满足"。

- 类别名写成中文或带空格 → 输入框实时校验 + `field__error`，不要等到提交才报错。
- 以为删除数据集会影响程序 → 页脚/帮助弹窗写明"删除数据集不会影响程序"。
- 把"0 张"当成"采集失败" → 空态文案写"还没有图片。选一个类别，先拍 20–30 张。"，而不是红色错误。

**命令四态（必须严格按这张表实现）**

| 状态 | 含义 | 视觉 | 文案 | 何时出现 |
| --- | --- | --- | --- | --- |
| 已发送 | 手机已发出，尚未收到回应 | 灰点 `--ink-4` + `--ink-2` 文字 | 「已发送」 | 请求发出、2 秒超时前 |
| 已接收 | 控制器确认收到了 | 蓝点（page CSS 新增 `.status__dot--info`：`--info` + 3px `--info-soft` 环）+ `--info` 文字 | 「已接收」 | 收到 `received` 回执 |

### 7.2 "不虚构数据"的 8 条硬规则

1. **数字只有三种来源**：实测（必须标口径）、示意（必须带「示意」角标）、未采集（`--`）。没有第四种。
2. **`null` 不是 `0`**：没采到写 `--`，JSON 里写 `null`。把未采集显示成 0 是最严重的失真。
3. **不做假进度**：不知道总量就不显示百分比，显示「准备中」+ 骨架条；不允许从 0 慢慢爬到 90% 再卡住。
4. **不做假成功**：一致性校验未通过时不得出现"已生成模型包"；命令只收到 `received` 时不得显示"已执行"。
5. **不做假连接**：原型里点"连接"后，必须出现「这是交互原型，不会真的连接设备」的 `.callout--warn`（`site.js` 已实现，照抄）。
6. **每张图都要说清身份**：画面类插图角标「示意画面 · 非真实设备」；指标卡角标「示意数据」；接线图角标「接线示意图，按你的板子核实」。
7. **不跨端相减时间戳**：不显示"端到端延迟"；本机间隔只用单调时钟。
8. **能力边界写在页面上，不只写在文档里**：`未接入`/`未验证`/`规划中` 必须在对应位置可见，而不是藏在 help 里。

### 7.3 数字口径速查

| 数字 | 归属 | 显示方式 | 出现位置 |
| --- | --- | --- | --- |
| 接收/显示帧率、丢帧、帧间隔 | 电脑实测 | 一位小数 + `.mono`，未连接 `--` | 实验台指标条、性能页 |
| 手机采集帧率 | 手机 `/ping.actualFps` | 一位小数；未连接 `--` | 实验台、性能页 |

| 功耗 | 不支持 | 「不支持」字样，无数字 | 性能页 |

## 9. 插画与图标清单

### 9.1 原则：插图解释知识，不做装饰

1. **一图一概念**：每张插图必须能回答"这一步在干什么"，图上至少要有 2 个标注（部件名、参数名、单位或口径）。没有标注的插图一律删掉。

## 10. 前端拆分建议

### 10.1 技术栈

**首选：继续用原生 HTML/CSS/JS**（与现状一致，零构建、`file://` 可打开、评审成本最低）。现有基础设施已经够用：`site.js` 提供 `PVL.progress`（localStorage 读写 + 自定义事件 `pvl:progress`）、`PVL.toast`、弹窗、筛选、进度渲染；页面级脚本各自独立。

### 10.4 状态管理

**状态形状（原生 JS 也照这个结构建对象，便于将来迁移）**

```js
// store.js —— 单一可变状态 + 订阅；不引框架也能用
const state = {
  connection: {
    status: 'idle',        // idle | connecting | connected | stale | error
    host: '', port: '8080',
    device: null,          // { status, device, width, height, requestedFps, actualFps, frameCount }
    lastFrameAt: 0,        // performance.now()，单调时钟
    error: null            // { code, message, hint }
  },
  dataset: {
    id: null, name: null,
    classes: [],                          // [{ name, count, batches }]
    check: { status: 'idle', issues: [] }, // idle | running | pass | warn | fail
    split: { done: false, seed: null, ratio: null }
  },
  training: {
    runId: null,
    status: 'idle',        // idle | blocked | running | failed | done
    epoch: 0, totalEpochs: 15,
    loss: null, valAcc: null, steps: 0,
    startedAt: 0, error: null
  },
  performance: {
    status: 'idle',        // idle | warmup | running | done | empty
    samples: [],           // { t, captureFps, recvFps, dispFps, dropped }
    nullKeys: []           // 明确记录哪些指标是 null（=未采集）
  },
  progress: { done: [], last: '' }        // 与 pvl.progress.v1 同步
};
```

**状态迁移（必须实现，禁止自造中间态）**

| 域 | 迁移 | 触发 |
| --- | --- | --- |
| connection | `idle → connecting → connected` | 用户提交连接 → `/ping` 成功 |
| connection | `connecting → error` | 超时 2s / 非 2xx / JSON 解析失败 |
| connection | `connected → stale` | 超过 3s 无新帧 |
| connection | `stale → connected` | 收到新帧 |
| dataset.check | `idle → running → pass\|warn\|fail` | 点击体检 → 结果返回 |
| dataset.split | `未划分 → 已划分` | 条件满足（≥2 类、每类 ≥2 批） |
| training | `idle → blocked` | 前置条件不满足 |
| training | `blocked → idle` | 条件补齐 |
| training | `idle → running → done\|failed` | 启动 / 结束 |
| training | `running → idle` | 用户取消（协作式，落盘当前状态） |
| performance | `idle → warmup → running → done` | 预热 3s 后开始计入 |
| performance | `running → empty` | 全程无帧 |

**持久化**：只有 `progress` 落 `localStorage`（键 `pvl.progress.v1`）。连接信息、数据集、训练任务**都不持久化**（原型无后端，不伪造"已保存"）。刷新后回到初始态，并在页面提示"原型状态不保存"。

### 10.5 请求层（为将来接入预留；当前原型全部关闭）

**先明确一件事**：现在的 `web-prototype` 没有后端，也没有网络层。下面这张表是"如果接入桌面客户端的本地 HTTP 服务"的契约，实现时必须放在 `const NET_ENABLED = false` 开关后面；关闭时适配器**返回 `{ unavailable: true }`**，界面进入"未连接/未接入"态，**绝不返回假数据**。

| 用途 | 端点 | 方法 | 超时 | 轮询 / 重连 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 连通性 | `http://{host}:{port}/ping` | GET | 2000ms | 连接前 1 次；连接后可选每 5s | 返回 `status/device/width/height/requestedFps/actualFps/frameCount`；`status != streaming` 时提示先点「开始推流」 |
| 画面 | `http://{host}:{port}/stream` | GET（长连接） | 无（流式） | 断线退避 1s / 2s / 3s，连续 3 次失败转手动重连 | `multipart/x-mixed-replace`；严格按 `Content-Length` 读；校验 `FF D8 … FF D9`；只保留最新帧；>3s 判 stale |
| 训练日志 | `http://127.0.0.1:{port}/runs/{runId}/log?offset={n}` | GET | 5000ms | 每 1000ms 一次，拿增量 | 结束条件：`done`/`failed`；连续 2 次失败 → 停止轮询并提示 |
| 取消训练 | `POST /runs/{runId}/cancel` | POST | 5000ms | 不自动重试 | 幂等；返回后轮询到 `idle` 才算取消成功 |
| 导出模型 | `POST /runs/{runId}/export` | POST | 30000ms | 不自动重试 | 返回 `{ passed, maxError, top1 }` |
| 性能导出 | `POST /perf/export?format=csv\|summary\|json` | POST | 10000ms | 不自动重试 | 产物在 `exports\` |

**MJPEG 客户端实现要点**（照 `protocol.md` 抄，别自己发明）：

1. 用 `fetch` + `ReadableStream` 读 `multipart`，按 `boundary` 切分；每段必须按 `Content-Length` 读满。
2. 每帧校验 SOI/EOI，坏帧计入 `invalid` 并丢弃，不显示。
3. 只保留最新帧（`latestFrame` 覆盖写）；消费慢时丢旧帧，不排队。
4. 用 `performance.now()` 记 `lastFrameAt`；超过 3000ms 置 `stale`。
5. 停止时 `AbortController.abort()`，并清空缓冲。

**训练日志轮询**：`offset` 游标增量拉取，单次最多 200 行；`TrainLog` 只保留最近 500 行（超出丢头部），自动贴底但用户手动上滚后暂停自动滚动。

### 10.6 错误处理策略

| 错误码 | 触发 | 界面 | 文案 | 动作 |
| --- | --- | --- | --- | --- |
| `NET_TIMEOUT` | `/ping` 2s 无响应 | 连接弹窗内 `.field__error` + 状态胶囊红点 | 「2 秒内没有响应。确认手机 IP、端口 8080、两台设备在同一 Wi-Fi。」 | 重试 / 改地址 / 看帮助 |
| `NET_REFUSED` | 连接被拒绝 | 同上 | 「对方拒绝连接。手机 App 的推流可能没开，或防火墙拦了 8080。」 | 重试 / 检查 App |
| `NET_BAD_JSON` | `/ping` 返回非 JSON | 同上 | 「返回的内容不是预期格式，可能不是 PhoneVision 的手机端。」 | 核对 IP |
| `HTTP_4XX` | 4xx | 同上 | 「请求被拒绝（HTTP {code}）。」 | 重试 |
| `HTTP_5XX` | 5xx | `.callout--warn` | 「手机端出错了（HTTP {code}）。重启 App 后再试。」 | 重试 |
| `STREAM_STALE` | 3s 无帧 | 画布降饱和 + 居中提示 | 「画面已中断 3 秒。」 | 重连 / 检查 Wi-Fi |
| `STREAM_BAD_FRAME` | 连续 10 帧校验失败 | 画布角标变黄 | 「画面数据异常，已丢弃 10 帧。」 | 重连 |
| `DEP_MISSING` | 训练依赖缺失 | `.callout--warn` + 前置条标红 | 「未检测到 TensorFlow…」 | 复制命令 / 看文档 |
| `DATA_UNBALANCED` | 体检严重失衡 | `.callout--warn` + 体检清单 | 「类别样本差距过大（最多 120 / 最少 8），建议补采少的类别。」 | 去采集 |
| `SPLIT_INSUFFICIENT` | 批次不足 | 划分按钮禁用 + 说明 | 「每类至少 2 个批次才能划分…」 | 继续采集 |
| `EXPORT_REJECTED` | 一致性未通过 | 弹窗 `.tag--danger` | 「校验未通过，已拒绝导出。」 | 查看原因 / 重新训练 |
| `PERF_EMPTY` | 无帧 | `.callout--warn` | 「没有采集到帧，报告会是空的。」 | 去连接 |

**统一规则**：① 错误文案三段式——**发生了什么 / 为什么可能 / 下一步做什么**；② 不显示原始堆栈，堆栈进"详情"折叠区；③ GET 可自动重试（最多 3 次，退避 1/2/3s），POST 一律不自动重试；④ 任何错误都不得把界面留在"看起来在加载"的状态。
