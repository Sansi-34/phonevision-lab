# PhoneVision Lab · Windows 客户端 UI/UX 方案（v1）

> 适用范围：`pc-client/qt_client`（PySide6 正式客户端）。
> 目标：把当前"单一画面工作台"升级为"五个模块 + 一条真实工作流"的教学型边缘 AI 工具，同时不虚构任何未验证能力。

---

## 0. 关于参考图

本方案以仓库里现有的 PySide6 工作台为分析基线（`docs/user-guide.zh-CN.md`、`qt_client/main_window.py`、`docs/images/workbench-zh.png`）。
若你手上有另一张更想对齐的效果图，把它发我，我按同一套令牌再对一遍细节；方法论和模块结构不需要变。

## 1. 我对项目的理解

PhoneVision Lab 不是监控软件，也不是"AI 训练平台"，而是一条**低成本边缘视觉闭环的实验流水线**：

```
手机(采集) → 电脑(看画面/采数据/训练/导出) → 手机(本机推理) → ESP32(执行) → 电脑(性能复盘)
```

三个角色的边界必须始终在界面上可见：

| 角色 | 负责 | 界面上必须体现 |
| --- | --- | --- |
| 旧手机 | 摄像头采集、本机 TFLite 推理、自动联动规则 | 手机端才有的功能要标注"手机端"，电脑端不放假开关 |
| 电脑 | 实时查看、传统视觉处理、数据集、训练、导出、手动测试、性能记录 | 训练环境是否可用要如实说明 |
| ESP32 | 接收命令、驱动 LED | 命令四态：已发送 / 已接收 / 已执行 / 失败 |

**用户画像**：学生、创客、AI 入门者，可能第一次接触"数据集/epoch/置信度"。他们要的不是参数自由，而是**"下一步做什么"**。
同时这个界面要能投屏路演——一屏之内，状态、进度、结果要一眼看懂，不用讲师解释。

**设计含义**：
1. 导航按**工作流顺序**排，不按技术模块名排。
2. 每个页面都要有"现在处于哪一步、下一步点哪里"。
3. 凡是"没有真实数据/没有真实反馈"的地方，用统一的能力标记（现有 / 未接入 / 未验证 / 规划中）说清楚，宁可不显示，也不填演示值。
4. 信息密度分层：默认只给结论（FPS、准确率、连接状态），细节（带宽、JPEG 大小、日志）折叠。

## 2. 参考图分析（现有工作台）

### 优点（应保留）

| 优点 | 说明 | 结论 |
| --- | --- | --- |
| 画面是唯一视觉核心 | 预览区占比大、纯黑画布、无多余装饰 | 保留，并强化 |
| 参数按模式生效 | 原始/灰度 0 个滑块、Canny 2 个、HSV 6 个、轮廓 7 个 | 保留这套"模式→参数"映射，改为分段控件 + 折叠分组 |
| 诊断分层 | 底部默认只显示 3 个 FPS，展开才看带宽/JPEG/计数 | 保留，作为"性能页"的入口雏形 |
| 断流有明确占位与内嵌重连 | 3 秒无帧显示居中提示 + 重连按钮 | 保留，补齐退避次数与已断时长 |
| 快捷键 + 双语 | 1-5 / S / R / Ctrl+Q，中英切换持久化 | 保留并扩到全站 |

### 不足

1. **产品定位偏差**：现在像"图像处理教学 + 推流查看器"，五件事（看、采、训、控、测）被压成一组顶部 Tab，用户看不出它们是一条流水线。
2. **垂直空间被 Tab 吃掉**：顶部 Tab + 标题在同一条线上，1366×768 下画面高度损失明显。
3. **配色的"信息噪声"**：主色用在按钮、选中态、状态灯、滑块多处，导致"哪个是主操作"不清晰；缺少中性层（surface-2）区分卡片层级，靠 1px 边框撑结构。
4. **字号偏小**：现有令牌 `SIZE_LABEL = 8pt / SIZE_STATUS = 9pt`，投影时后排看不清；最小可用正文建议 12–13px。
5. **状态语义不够系统**：连接中 / 重连中 / 无帧 / 训练中 / 未接入，颜色和措辞不统一，学习者容易把"已发送"读成"已执行"。
6. **跨模块上下文断裂**：在实时视觉页看不到"现在采到哪个数据集/类别"，到数据集页又看不到画面，采集时来回切 Tab。
7. **能力边界不显性**：训练环境不可用、手机推理数据未接入、硬件未验证——这些在界面上是"一处说明"而不是"结构化能力标记"，容易被误读为已实现。

### 与真实流程的偏差

- 真实流程里 **采集必须一边看画面一边拍**，而现在的采集控件在另一个 Tab；
- **训练的前置条件**（≥2 类别、每类 ≥2 批次、已划分）散落在文档里，界面上没有"体检 → 划分 → 训练"的强制引导；
- **导出与部署**是两次系统边界切换（导出 → 拷贝到手机 → 导入），界面没有"部署清单"把这件事说清；
- **硬件自动联动在手机端**，电脑端若放开关就是假控件——现有代码已做了拦截（无预测源时不允许开启），但 UI 上应升级为"能力说明卡"而不是一个灰掉的复选框。

## 3. 整体设计方向

### 3.1 视觉关键词

`实验室仪器 / 工业 HMI / 冷静 / 高信噪比 / 可投屏`

- 深色为底，**大面积中性灰蓝**，强调色只出现在"可点击"和"当前状态"上；
- 布局用**留白与层级底色**分层，边框尽量细（1px，#232B36），不用阴影和渐变；
- 数字用等宽字体，单位小型化；状态一律"色点 + 文字"，不靠颜色单独表达；
- 动效只保留必要的两处：连接状态呼吸点、连续采集时的录制点闪烁（≤ 1.2s 周期）。

### 3.2 信息架构

```
┌──────────────────────────────────────────────────────────────────────┐
│ TopBar  品牌 · 设备连接胶囊 · 流程进度 · 语言 · 帮助                    │ 56
├──────────────────────────────────────────────────────────────────────┤
│ PipelineBar  ① 连接 ② 采集 ③ 训练 ④ 导出 ⑤ 手机导入 ⑥ 硬件联动        │ 34
├──────┬───────────────────────────────────────────────────────────────┤
│ Nav  │  Page（QStackedWidget，五个模块）                              │
│ Rail │                                                               │
│ 72   │                                                               │
├──────┴───────────────────────────────────────────────────────────────┤
│ StatusBar  连接 · 采集/接收/显示 FPS · 丢帧 · 当前数据集/类别 · 诊断    │ 30
└──────────────────────────────────────────────────────────────────────┘
```

导航顺序 = 工作流顺序（这是本方案最关键的改动）：

| # | 模块 | 一句话职责 | 何时进入 |
| --- | --- | --- | --- |
| 1 | 实时视觉 | 连上手机、看画面、调传统视觉、顺手截图 | 每次进来默认页 |
| 2 | 数据集 | 建数据集/类别、采图、体检、划分 | 需要样本时 |
| 3 | 模型训练 | 配置、训练、看曲线、导出模型包 | 样本够了 |
| 4 | 硬件联动 | 连控制器、手动测灯、看事件、理解四态 | 想联动时 |
| 5 | 性能分析 | 采样、看口径、导出报告 | 验收/汇报时 |

底部：`设置`（主题/语言/数据目录/快捷键）与 `关于`（版本、许可证、能力清单）固定在 Nav Rail 底部。

**流程进度条（PipelineBar）**：6 个步骤圆点 + 文案，状态为 `未开始 · 进行中 · 已完成 · 需重做`。
其中 ⑤⑥ 属于手机端，电脑无法自动判定，**只能由用户点"标记为已完成"**，未标记时显示"待你在手机端完成"，绝不自动打勾。

### 3.3 配色

深色单主题（v1 只做深色，浅色作为后续开关预留）。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `bg` | `#0E1116` | 窗口底色 |
| `surface` | `#161B22` | 卡片/面板 |
| `surface2` | `#1C232D` | 卡片内二级块、输入框、表头 |
| `hover` | `#222A36` | 悬停/按下底 |
| `border` | `#232B36` | 常规描边（1px） |
| `border_hi` | `#2E3845` | 分隔线、聚焦前边框 |
| `text` | `#E6EAF0` | 主文本（对比度 ≈ 14:1） |
| `text2` | `#9AA5B4` | 次要文本/标签（≈ 7:1） |
| `text3` | `#6B7684` | 弱提示、单位（仅辅助信息） |
| `primary` | `#3B82F6` | 主操作按钮、选中项、焦点环 |
| `primary_hover` | `#5B9AF8` | 主按钮悬停 |
| `primary_soft` | `rgba(59,130,246,.14)` | 选中行底、选中导航底 |
| `cyan` | `#22D3EE` | 实时数据强调（LIVE 点、曲线、FPS 数值） |
| `success` | `#34D399` | 已连接 / 已完成 / 已执行 |
| `warning` | `#F5B942` | 重连中 / 未验证 / 需注意 |
| `danger` | `#F87171` | 失败 / 错误 / 破坏性操作 |
| `info` | `#60A5FA` | 进行中 / 说明性标注 |

用法约束（很重要，避免现在"到处都是蓝"的问题）：

- **实心主色只给每屏唯一的主按钮**（如"开始训练""连接手机"）；
- 次级按钮：透明底 + 1px `border_hi` + `text`；
- 危险按钮：默认透明底 + `danger` 文字，悬停才填充 `danger` 底（防误点）；
- 状态色只用于**点/图标 + 文字**，不整块填充；整块填充仅用于顶部 banner（低饱和底）。

### 3.4 字体

| 级别 | 字号/字重 | 用途 |
| --- | --- | --- |
| Display | 24px / 600 | 页面主标题（仅一屏一个） |
| H2 | 16px / 600 | 卡片标题、分区标题 |
| Body | 13px / 400 | 正文、列表、按钮文字（最小正文） |
| Label | 12px / 400 | 表单标签、表头、说明 |
| Caption | 11px / 400 | 单位、辅助注、时间戳（最小可读） |
| Metric | 22–26px / 600 + mono | 关键指标数值（FPS、准确率） |
| Mono | 12px | 日志、IP、requestId、耗时 |

- 中文：`Microsoft YaHei UI`；西文：`Segoe UI Variable Text` → `Segoe UI`；等宽：`Cascadia Mono` → `Consolas`。
- 复用现有 `qt_client/fonts.py` 的字体加载与回退逻辑，不要另建一套。
- 一律用 **px** 写 QSS（`font-size: 13px`），不要用 pt，避免 125%/150% 缩放下跳动。

### 3.5 间距与尺寸

4pt 栅格：`4 / 8 / 12 / 16 / 24 / 32 / 48`。

| 场景 | 值 |
| --- | --- |
| 页面外边距 | 24 |
| 卡片内边距 | 16（紧凑 12） |
| 卡片间距 | 12（同组）/ 24（跨组） |
| 表单行高 | 40（标签 12px + 控件 28） |
| 控件高度 | 32（常规）/ 36（主按钮、连接框） |
| 图标 | 16（行内）/ 20（按钮）/ 24（导航） |
| 顶栏 / 流程条 / 状态栏 | 56 / 34 / 30 |
| Nav Rail | 72（展开）/ 56（收起，仅图标） |

### 3.6 圆角、边框、层级

- 圆角：`6`（chip/badge）、`8`（按钮/输入）、`10`（卡片）、`12`（对话框）、`999`（胶囊）。
- 边框：常规 1px `border`；聚焦 2px `primary`（内描边，用 `outline` 或双层 QFrame 实现）；错误态 1px `danger` + 下方 11px 红字说明。
- 分层只靠"底色 + 边框"，**不用阴影**（QSS 阴影性能差且在深色上不明显）。
- 焦点可见：所有可交互控件必须有 `:focus` 样式（键盘可达，路演时常用 Tab 演示）。

### 3.7 组件风格

- 卡片 = `surface` + 1px `border` + 10px 圆角 + 标题行（16px/600 + 右侧操作）。
- 状态胶囊 = 8px 圆点 + 12px 文字 + `surface2` 底 + 999 圆角；四态色见 §7。
- 表格 = 无竖线、行高 32、斑马纹用 `surface2` 的 40% 透明，不用纯色交替。
- 所有"未接入/未验证"用统一 `CapabilityBadge` 文案：`现有` / `未接入` / `未验证` / `规划中`。

## 4. 五个模块页面方案

### 4.1 实时视觉（Live）

**目标**：一屏完成"确认连上了、看清画面、切处理模式、顺手存一张图"。

**信息层级**
1. L1：画面是否在动、连接是否正常（预览 + 状态胶囊 + FPS）
2. L2：当前模式与参数（右侧检查器）
3. L3：采集上下文（当前数据集/类别，底部 Chip）
4. L4：诊断细节（带宽、JPEG、计数，折叠）

**区域划分**：`顶栏` / `预览区（flex）` / `右侧检查器 300px` / `底部状态栏`。详见 §5。

**关键按钮与状态**

| 元素 | 状态逻辑 |
| --- | --- |
| 连接/断开 | 未连接→`连接手机`（主按钮，打开连接对话框）；已连接→`断开`（次级，二次确认仅在采集进行中） |
| 模式分段控件 | 5 项，键位 1–5；切换立即生效、不重置滑块值（每模式记住自己的参数） |
| 参数滑块 | 按模式渲染；原始模式无滑块→显示"原始模式无参数"空态，不隐藏整块（避免布局跳动） |
| 截图 S | 未连接时禁用 + tooltip"连接手机后才能截图"；成功后 Toast"已保存到 captures/…"并给"打开目录" |
| 单张采集 | 未选数据集/类别→禁用并提示"先在右侧选择数据集与类别" |
| 连续采集 | 三段式：`开始`（primary）→ `停止`（danger 描边）+ 录制点闪烁 + 已采 N 张 → 停止后 Toast 带张数与批次号 |
| 冻结画面 F | 纯显示层暂停（后端继续接收），角标显示"已冻结 · 实时仍在接收" |
| 全屏 / 适应窗口 | 纯前端缩放，不影响后端 |

**新手容易遇到的问题 → 提示**

| 问题 | 界面提示 |
| --- | --- |
| 滑块拖了没反应 | 参数区标题旁常驻小字："仅影响当前模式（Canny）"；切模式时 Toast 提示"已切到 HSV，参数已切换" |
| 以为画面卡住 | 断流 > 3s：画面中央显示"画面已中断 12 秒，正在第 2 次重连（3 秒后）"+ 倒计时；不显示最后一帧假装还在跑 |
| 不知道图存哪了 | 采集上下文条常驻："保存到 数据集 my-objects / 类别 apple"，点开可"打开文件夹" |
| Canny 滑块无效 | 已知环境 bug（OpenCV 5.0.0）：检测到阈值不生效时，参数区顶部黄色 banner："Canny 阈值在本机 OpenCV 版本下不生效，可改用 HSV / 轮廓模式体验" |

### 4.2 数据集（Dataset）

**目标**：让"采什么、存到哪、够不够训"三件事一目了然，并把"体检 → 划分"变成训练前的必经关卡。

**信息层级**
1. L1：当前数据集体检结论（可否训练）
2. L2：类别与每类数量
3. L3：缩略图（按批次分组）
4. L4：批次/划分/种子等技术细节

**区域划分**

```
┌ 左栏 280 ─────────┐┌ 主区（flex）───────────────────────────────┐┌ 右栏 320 ────────┐
│ 数据集            ││ 类别 Tabs: [apple 42] [banana 38] [+ 新建] ││ 采集              │
│ [搜索____]  [新建]││ ───────────────────────────────────────── ││ 数据集/类别（只读）│
│ ▸ my-objects  80  ││ 工具栏: 采集一张 | 连续采集 | 间隔 500ms   ││ 单张 / 连续        │
│ ▸ led-demo    36  ││        体检 | 划分训练/验证 | 删除所选    ││ 本次批次 18 张     │
│                   ││ ───────────────────────────────────────── ││ ─────────────    │
│                   ││ 批次 2026-08-12 14:31（18） ▾             ││ 体检结果           │
│                   ││ [img][img][img][img][img][img]            ││ ✓ 2 类别 / 4 批次  │
│                   ││ 批次 2026-08-12 14:12（24） ▾             ││ ⚠ 每类建议 ≥ 80 张 │
│                   ││ [img][img][img]...                        ││ [去体检] [去划分]  │
└───────────────────┘└───────────────────────────────────────────┘└──────────────────┘
```

**关键按钮与状态**

- `新建数据集`：对话框（名称 + 初始类别，支持逗号分隔批量）；名称实时校验（仅字母数字 `_-.`），重名内联报错。
- `新建类别`：内联输入 + 回车提交；规范化后的目录名实时显示在下方小字。
- `采集一张 / 连续采集`：与实时视觉共用同一采集服务，按钮状态互斥（连续采集中单张禁用）。
- `数据体检`：结果以清单呈现，每条含"严重度图标 + 问题 + 一句话解决建议 + 跳转"。
- `划分训练/验证`：显示 `训练 64 / 验证 16 · 按批次 · seed 1234 · 2026-08-12 15:02`；数据集变更后标记"划分已过期，请重新划分"。
- `删除`：单图可直接删（可撤销 5 秒）；删类别/删数据集需输入名称确认。

**新手坑 → 提示**

| 坑 | 提示 |
| --- | --- |
| 只拍了一个批次 | 体检卡红条："每类至少 2 个批次才能划分验证集（同一批次相邻帧不拆开，否则准确率虚高）"，并给"如何分批拍"的一行说明 |
| 类别不均衡 | "banana 38 张 / apple 42 张"正常；比例 > 3:1 时黄条提示"样本比例差异大，模型可能偏向多数类" |
| 采集时不知道存哪 | 右栏顶部常驻读数："正在存入 my-objects → apple"；同时实时视觉页显示同一上下文 |
| 图片打不开 | 体检里列出文件名与原因，提供"移出数据集"而非静默跳过 |

### 4.3 模型训练（Train）

**目标**：让人看懂"能不能训、训到哪了、训完能不能用"，并且不以假进度掩盖环境缺失。

**信息层级**
1. L1：训练环境是否可用 + 数据是否就绪
2. L2：进度与关键指标
3. L3：日志
4. L4：导出结果与一致性校验

**区域划分**


### 4.5 性能分析（Performance）

**目标**：让"三个 FPS 不是一回事"这件事被看见，并明确报告里到底有什么、没有什么。

**信息层级**
1. L1：本次测试是否在采样 + 采样口径（预热/时长）
2. L2：采集与传输三项真实指标
3. L3：未接入项（推理/硬件/功耗）的明确"未采集/不支持"
4. L4：导出与报告说明

**区域划分**

```
┌ 测试控制条 ────────────────────────────────────────────────────────────┐
│ 预热 [3]s  时长 [60]s  [开始测试]  ● 采样中 00:42/01:00  [停止]        │
├ A 采集与传输（电脑实测）───────────────────────────────────────────────┤
│ 手机采集 FPS  电脑接收 FPS  电脑显示 FPS  丢帧    分辨率   带宽        │
│   15.0          14.8           14.2         3      640×480  8.5 Mbps   │
│   口径：手机 /ping 自报 | PC 每秒解析成功率 | PC 实际绘制帧数           │
├ B 手机推理（未接入）──────────────┬ C 硬件联动（未接入）────────────────┤
│ 推理 FPS      未采集              │ 命令数 / 已执行   未采集            │
│ 预处理/模型/后处理  未采集        │ 规则延迟 / RTT    未采集            │
├ D 功耗 ──────────────────────────┴─────────────────────────────────────┤
│ 不支持：PC 客户端不测量手机功耗。仅当设备提供真实电流/电压源时才显示，  │
│ 并区分 实测 / 估算 / 电量变化。                                        │
├────────────────────────────────────────────────────────────────────────┤
│ [导出 CSV] [导出摘要] [导出 JSON]   ▸ 本次报告包含哪些指标（12 项）     │
└────────────────────────────────────────────────────────────────────────┘
```

**关键按钮与状态**

- `开始测试`：要求已连接（否则禁用 + 原因）；预热期显示"预热中，不计入统计"；
- `停止`：提前结束，报告标记 `提前结束（42/60s）`；
- 导出三格式：文件名带时间戳；导出后 Toast + "打开目录"；
- `本次报告包含哪些指标`：折叠清单，逐项标 `已包含 / 未采集 / 不支持`，与 JSON 字段一一对应。

**数据诚实规则（必须实现）**
1. `未采集` 用破折号 `—` + 灰字，**不是 0**；`0` 只在"确实测到 0"时出现，并加 tooltip"采集到 0 帧/秒"。
2. 手机推理、硬件耗时的数值来自手机上报；PC **绝不**用两端时间戳相减算端到端延迟。
3. 功耗固定 `不支持`，除非存在真实数据源。

**新手坑 → 提示**

| 坑 | 提示 |
| --- | --- |
| 三个 FPS 混为一谈 | 每个指标卡下方一行 11px 口径说明（见上图）；悬停有完整解释 |
| 以为 `—` 是 0 | 图例："— 表示未采集，不代表 0" |
| 测完不知道报告里有什么 | 导出清单 + 报告首段自动写"本报告包含 X 项传输指标；手机推理/硬件/功耗数据未接入" |

## 6. 从"连接旧手机"到"训练并部署"的新手流程

以"第一次使用的学生"为视角，每一步都给出**界面反馈**与**失败时的出路**。

| # | 用户动作 | 界面反馈 | 卡住时的提示 |
| --- | --- | --- | --- |
| 0 | 打开客户端 | 空状态：大标题"先把旧手机连上"，三步图（同 Wi-Fi → 手机开推流 → 填 IP）+ `连接手机` | 附"手机端怎么开推流"的 3 行说明 + 二维码/链接 |
| 1 | 填 `192.168.2.14:8080` | 连接对话框显示步骤化检测：`端口可达 → /ping 成功 → 读取设备信息`，每步独立打勾/打叉 | 打叉行直接给原因：不同网段 / 手机未点开始推流 / 防火墙拦截 |

| 3 | 试 2 分钟各模式 | 右侧切换灰度/Canny/HSV/轮廓，参数即时生效；原理提示展开 | Canny 阈值不生效 → 黄色 banner 指向环境 bug |
| 4 | 切换"数据集" | 无数据集空态："还没有数据集"+ `新建数据集` | 名称规则内联提示 |
| 5 | 建 `my-objects` + 类别 `apple` `banana` | 类别 Tab 出现，计数 0；右侧采集面板显示"存入 my-objects → apple" | 少于 2 类别时提示"至少 2 个类别才能训练" |
| 6 | 回实时视觉连续采集 | 录制点闪烁、计数递增、批次号生成；停止后 Toast"本批次 24 张" | 采集时断流：自动停止采集并保留已存图片，明确提示已保存张数 |
| 7 | 换角度再拍 ≥2 批次/类 | 缩略图按批次分组；右栏体检卡实时更新（✓/⚠/✗） | 只有 1 批次 → 红条拦截并解释数据泄漏 |
| 8 | 数据体检 → 划分 | 体检全绿；划分完成显示 `训练 64 / 验证 16 · seed 1234`；Pipeline ② 打勾 | 划分后新增图片 → 标"划分已过期，需重新划分" |
| 9 | 进入"模型训练" | 数据集卡片自动带入类别与数量；参数默认值已填好；环境卡状态明确 | 环境不可用 → 给出 `start-training.cmd` 或安装命令，`开始训练` 禁用并说明原因 |
| 10 | 点开始训练 | 进度条 + epoch/step + loss/acc 实时刷新；Nav 训练项显示进度环；顶栏胶囊"训练中 47%" | 训练失败 → 分型错误 + 日志定位 + 建议 |
| 11 | 训练完成 → 导出 | 结果卡（最佳 val_acc、每类准确率）；导出一致性：最大误差 0.012 ✓ / Top-1 99% ✓ → "导出成功" + 路径 | 一致性不通过 → 明确拒绝 + 原因与建议，不产出模型包 |
| 12 | 部署到手机 | 部署清单卡（4 步）：① 传输 `xxx.pvlmodel.zip` 到手机（USB/文件传输/`adb push`）② 手机打开"本机 AI 推理" ③ 导入模型包 ④ 看到"预测类别 + 置信度"才算成功。每步可手动勾选，勾完 Pipeline ⑤ 打勾 | 导入被拒 → 提示按报错原因核对（版本/尺寸/颜色顺序/归一化），并链到手机端说明 |
| 13 | 离线验证 | 清单加一条："断开电脑与 Wi-Fi，手机仍能推理"（勾选后记录时间） | 失败 → 说明推理离线但硬件通信需同网 |
| 14 | 硬件联动 | 电脑端手动测灯（四态可见）；自动控制在手机端开启 | 电脑端不出现自动开关，只有"为什么"+步骤 |
| 15 | 性能复盘 | 采样 60s → 导出报告；报告首段写明包含/未包含项 | `—` 与 `0` 的区别在页面图例中说明 |

**关键原则**：PipelineBar 的 ⑤⑥ 只能人工标记；任何"看起来自动完成"的勾选都是欺骗。

## 7. 关键状态设计

### 7.1 空状态

| 场景 | 表现 |
| --- | --- |
| 首次启动未连接 | 预览区大空态（标题 + 3 步 + 主按钮）；右侧参数区置灰但可见；状态栏 `未连接` |
| 无数据集 | 数据集页居中空态 + `新建数据集`；实时视觉采集区显示"未选择数据集（点此创建）" |
| 数据集无图片 | 网格区空态："这个类别还没有图片"+ `去实时视觉采集` |
| 无模型 | 训练页结果区空态："还没有训练记录"；部署清单卡整体灰但可读 |
| 无控制器 | 硬件页连接卡空态 + 地址输入 + "如何烧录固件"链接 |
| 无性能数据 | 性能页卡片全部 `—` + 图例"未采集 ≠ 0" |

### 7.2 断连（分级）

| 级别 | 触发 | UI |
| --- | --- | --- |
| L1 短暂抖动 | 1–3s 无帧 | 预览区右上角小黄点 + "网络抖动"；不清画面 |
| L2 断流 | >3s | 清空画面；居中"画面已中断 12s，正在第 2 次重连（3s 后）"+ `立即重连`；顶栏胶囊变黄"重连中" |
| L3 长时断开 | >60s | 追加"手机可能已停止推流或被系统杀掉后台，请回到手机 App 重新开始推流"；连续采集自动停止并汇总"本次已保存 18 张" |
| L4 启动即失败 | /ping 失败 | 连接对话框内联错误 + 三步排查清单；不弹裸技术异常 |

### 7.3 训练中 / 训练失败

- 训练中：参数控件锁定（tooltip"训练进行中，参数已锁定"）；允许切页但顶栏常驻进度胶囊；`取消训练` 二次确认；关闭窗口需确认"训练将中断"。
- 训练失败分型：`环境缺失` / `依赖导入失败` / `数据不足` / `内存或显存不足` / `数值异常(NaN)` / `导出校验未通过`，每型给一句可执行建议 + 日志中定位到首行错误。

### 7.4 未采集数据

- 统一符号 `—`（`text3` 色），旁边 11px "未采集"；tooltip 说明为什么没有（"手机端尚未上报"）。
- `0` 只用于真实测得的 0，并附"采集到 0 帧"的说明，避免与"没测"混淆。
- 性能报告 JSON 中未采集为 `null`，导出清单里逐项标注。

### 7.5 硬件未验证

- 硬件页顶部常驻 `CapabilityBadge: 未验证` + 一句结论（"协议与固件已实现，真实 ESP32 与 LED 尚未完成端到端验证"）。
- 使用模拟设备时页面变红条"模拟设备"；切回真实设备后红条消失。
- 命令状态时间线：`已发送 → 已接收 → 已执行`，缺哪一段就停在哪一段，未收到 `executed` 时**不出现绿色成功**。

### 7.6 旧模型 / 预处理变更

- 检测到模型包 `preprocess` 契约版本与当前训练/导出流程不一致时：训练页与部署清单同时显示黄色 banner："该模型由旧预处理流程生成，手机端可能预测不准，建议重新训练并重新导出。" 并提供"查看差异"。
- 数据集改动后：`划分已过期` 徽章 + 一键重新划分。

### 7.7 长文本与错误详情

- 列表内截断用 `ElideMiddle` + tooltip 全文；IP、路径等用等宽字体；
- 错误一律"一句话结论 + 详情折叠 + 复制错误信息"三段式，禁止把 Python traceback 直接铺在界面上。

**职责边界（必须遵守）**
- `pages/*` 只做布局与交互，**不直接**发 HTTP、不跑 OpenCV、不跑训练；全部通过注入的服务对象 + 信号。
- 所有阻塞操作走 `QThreadPool` / `QThread` + `Signal`；UI 线程只做绘制与状态更新。
- 面板之间通过 `app_state` 通信（例如"当前类别"），禁止互相 import 对方控件。
- 现有 `dataset_panel / train_panel / hardware_panel / perf_panel` 的业务逻辑可整段搬进 `pages/*`，只重写视图层。

## 9. 开发优先级

| 优先级 | 内容 | 为什么先做 | 验收 |
| --- | --- | --- | --- |
| **P0** | `tokens.py` + `style.py` 统一 QSS；把顶部 Tab 换成 NavRail + QStackedWidget；底部全局 StatusBar；PipelineBar 骨架（状态可手动推进） | 这是"从监控软件变成流程工具"的结构性改动，后面所有页面都挂在上面 | 五个页面可切换；窗口 960×640 与 1366×768 不裁字；现有功能全部可达 |

| **P1** | 数据集体检/划分结果结构化展示（红黄绿清单 + 跳转） | 训练前必经关卡，防止数据泄漏式假指标 | 单批次时训练按钮禁用并说明原因 |
| **P2** | 训练页：环境卡（可用/不可用/检测中）、进度+日志、取消确认、结果卡、导出一致性 | 训练是最"黑箱"的环节 | 环境不可用时 `开始训练` 禁用且给出两条修复路径 |

**排期建议（单人）**：P0 结构 2–3 天 → 实时视觉 2 天 → 数据集 2 天 → 训练 2–3 天 → 硬件 1–2 天 → 性能 1–2 天 → 打磨 2 天。
