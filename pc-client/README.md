# PhoneVision Lab — PC 端一体化 GUI 客户端

把闲置的旧手机变成一台"IP 摄像头"：手机 App 推送 MJPEG 视频流，PC 端用一个
**一体化 Tkinter 窗口**实时接收并学习图像处理。本目录就是 PC 端程序。

## 项目简介

手机端 App 启动后，在同一个 WiFi 下向电脑持续推送
`multipart/x-mixed-replace` 格式的 MJPEG 流。`mjpeg_reader.py` 在后台线程严格按
boundary + Content-Length 解析每一帧 JPEG，**只保留最新一帧**（处理慢也只落后
一帧，延迟不会随时间累积）；断线会自动按 1/2/3 秒退避重连。`main.py` 只负责
解析命令行参数、启动前检查 `/ping`，然后把流交给 `app_gui.py` 的**一体化 GUI**
显示和调参——画面区、命令台、状态栏都在一个窗口里，滑块拖动即可实时观察每个
图像处理步骤。

## 环境要求

- Windows / macOS / Linux 均可，Python **3.12 或更高**
- 安装依赖（建议先建虚拟环境）：

  ```
  pip install -r requirements.txt
  ```

  依赖列表：`opencv-python`（图像处理）、`numpy`（图像数组）、`requests`
  （HTTP 拉流）、`pillow`（把 OpenCV 帧转成 Tkinter 可显示的图像）。

## 启动命令

先启动手机 App 开始推流，然后在电脑上运行：

```bash
# 方式一：用 host + 端口（App 默认推流端口，通常就是 8080）
python main.py --host 192.168.2.14 --port 8080

# 方式二：直接用完整流地址
python main.py --stream-url http://192.168.2.14:8080/stream
```

> 注意：IP **不硬编码**。上面 `192.168.2.14` 只是示例，请替换成**你自己手机
> App 界面显示出来的 IP 地址**（不同 WiFi 下会不一样）。

启动时程序会先访问 `http://<手机IP>:8080/ping` 确认手机在线并打印手机信息
（型号、分辨率、采集 FPS、状态）。**检查失败会给出中文错误提示并退出**，按提示
逐条排查即可（手机没推流 / 不在同一 WiFi / IP 填错）。`/ping` 通过后自动打开
GUI 窗口。

## GUI 界面说明

一个窗口 = 三个区域，全鼠标操作：

```
┌──────────────────────────────────────────────┐
│              顶部：视频画面区                  │
│   （显示当前模式的处理结果，自动等比缩放）      │
├──────────────────────────┬───────────────────┤
│  左侧：命令台             │   顶部画面区       │
│  视觉模式：原始 灰度      │   （同上区域）     │
│             Canny HSV 轮廓│                   │
│  当前: 原始              │                   │
│  参数调节（按模式生效）：  │                   │
│   Canny Low [────●──] 50  │                   │
│   Canny High [──●────] 150│                   │
│   H Min [─●──────] 0      │                   │
│   H Max [───────●] 179    │                   │
│   S Min / S Max / V Min / │                   │
│   V Max / Min Area        │                   │
│   [保存S] [重连R] [退出Q]  │                   │
├──────────────────────────┴───────────────────┤
│  底部：状态栏                                  │
│  模式:原始 状态:Streaming 采集FPS:15.0         │
│  接收FPS:14.8 显示FPS:14.8 640x480            │
│  JPEG:0.72MB 带宽:8.5Mbps                     │
│  收:284 无效:0 丢:0  错误:...                  │
└──────────────────────────────────────────────┘
```

- **顶部画面区**：实时显示当前模式的输出；没连上时显示"等待画面 / 连接断开，
  正在重连..."。
- **左侧命令台**：
  - 5 个模式按钮（`1 原始` / `2 灰度` / `3 Canny` / `4 HSV` / `5 轮廓`），
    下方有"当前: 模式"提示。
  - 参数滑块（按模式生效）：Canny Low / Canny High、H/S/V 的上限与下限
    （共 6 个）、Min Area。**拖动滑块实时生效**，改完马上看画面变化。
  - 动作按钮：`保存 S`（把原图和处理图存到 `captures/`）、`重连 R`、
    `退出 Q`。
- **底部状态栏**：一行显示所有关键信息——模式、状态（Streaming /
  Reconnecting）、**三个 FPS**（采集=手机端实际帧率、接收=PC 解析成功的
  帧/秒、显示=PC 处理并显示的帧/秒）、分辨率、平均 JPEG 大小、网络带宽、
  已收/无效/丢帧计数，以及最近的错误信息。**这是观察"卡在哪一环"的窗口**：
  显示 FPS 明显低于接收 FPS，说明是本机处理慢。

## 视觉学习意义

这套程序不是为了"跑通"，而是让你**亲手拖动滑块**，亲眼看到每一步图像处理
到底发生了什么。五个模式本身就是最经典的图像处理入门路线。

### 灰度（按钮 `2 灰度`）

去色，把三通道的彩色图压成单通道亮度图。很多算法（如 Canny、轮廓）都在灰度上
运算，因为颜色对它们来说是噪声，灰度更"纯粹"，计算量也小。

### Canny 边缘检测（按钮 `3 Canny`，滑块 Canny Low / Canny High）

`cv2.Canny(gray, low, high)` 需要两个阈值，判断依据是每个像素的**梯度幅度**
（亮度变化剧烈程度）：

- 梯度 < `low`：丢弃；
- 梯度 > `high`：必定保留为边缘；
- 梯度**介于 low 与 high 之间**：只在它连接着一条强边缘时才保留。

所以 **low/high 越高，检测越严格、边缘越少越干净**；越低则细节越多、噪声越多。
把手机对准一个物体，拖动"Canny Low/High"两个滑块，体会"严格程度"的含义——
找到一个"边缘刚好连成轮廓、又没有太多碎线"的平衡点。

> 已知限制：OpenCV 5.0.0 在部分 Windows 环境下 Canny 阈值不生效（边缘显示
> 固定不变）。**这是环境级 bug，不是你的操作问题。** 这种情况下 Canny 仍能
> 显示边缘，但滑块不动，请改用 HSV / 轮廓模式体验调参，或换 OpenCV 版本。

### HSV 颜色分割（按钮 `4 HSV`，滑块 H/S/V 上下限共 6 个）

HSV 相比 RGB 更接近人类的感知：

- **H（色相）**：颜色本身，在圆环上的角度（OpenCV 里范围是 **0~179**）；
- **S（饱和度）**：颜色的鲜艳程度（0~255）；
- **V（明度）**：颜色的亮暗（0~255）。

RGB 里"红色"要靠三个通道同时猜，而在 HSV 里只需要给 H 一个区间，就能把画面里
所有偏红的像素单独抠出来。画面中**白色 = 选中的像素，黑色 = 被过滤掉的**。

动手练习：拖动 H 上下限圈住一个颜色的物体，再微调 S/V 排除背景——你会发现
"颜色其实是**连续的一段范围**，不是精确的一个值"。这也是光照变化时颜色分割
不稳定的根本原因，理解这一点，你就懂了颜色检测的难点在哪。

### 轮廓检测（按钮 `5 轮廓`，滑块 Min Area + 6 个 HSV 滑块）

基于上面 HSV 分割出的**掩膜**，用 `cv2.findContours` 找出连通的区域轮廓。
拖动 **Min Area**（默认 500）过滤掉面积太小的噪点块。每个轮廓会画出：

- 绿色：轮廓本身
- 蓝色：外接矩形
- 红色：矩形中心点 + 坐标

这就是**最简单的目标检测**——识别出"画面里有东西、它在哪"，是后续做定位、
跟踪、测距的基础。练习方式：先用 HSV 滑块把目标颜色圈出来，再调 Min Area
把噪点滤干净，最后看中心坐标在目标移动时如何变化。

## 已知限制

- **Canny 阈值在 OpenCV 5.0.0 下可能不生效**（部分 Windows 环境，边缘显示
  固定）。环境级 bug；HSV 颜色分割和轮廓检测不受影响。
- **Windows 高 DPI 下不用 OpenCV trackbar**：本机 HighGUI 的 trackbar 拖动
  不更新值，是 OpenCV 环境级 bug。因此 GUI 用 **Tkinter 滑块**替代，跨环境
  100% 可靠。
- 当前仅支持**单客户端**连接（V0 范围）。

## 常见问题

- **连不上（启动时报中文错误 / /ping 失败）**：确认手机 App 正在推流、手机和
  电脑在**同一个 WiFi**，并在浏览器打开 `http://<手机IP>:8080/ping` 应能看到
  响应。IP 填错也会连不上，以 App 界面显示的 IP 为准。
- **画面不动（状态栏显示 Reconnecting）**：说明流断了、正在自动重连。多半是
  手机推流已停止（App 退到后台被系统杀掉）。回到 App 重新开始推流，或点
  `重连 R`。
- **滑块没效果**：先确认**模式有没有切对**——Canny 滑块只影响 Canny 模式，
  HSV/轮廓滑块只在 HSV/轮廓模式生效。切到对应模式再拖滑块。
- **延迟偏高**：MJPEG 每帧都是一张完整 JPEG，不做帧间压缩，带宽占用和延迟天然
  比 H.264 高，这是它的固有特性。把手机分辨率/码率调低能明显改善。
- **提示缺依赖 / 找不到 cv2**：先 `pip install -r requirements.txt`，确认装在
  你运行 `python` 的那个环境里。

## 目录结构

```
pc-client/
├── main.py                # 入口：命令行参数、/ping 检查、启动 GUI
├── app_gui.py             # 一体化 Tkinter GUI：画面区 + 命令台 + 状态栏
├── mjpeg_reader.py        # MJPEG 流接收器：拉流、解析、断线重连（只留最新帧）
├── vision_modes.py        # 5 种 OpenCV 处理模式（灰度/Canny/HSV/轮廓）+ 参数
├── requirements.txt       # Python 依赖（含 pillow）
├── captures/              # 点"保存 S"后存的原图 + 处理图
└── tests/
    └── test_mjpeg_reader.py   # 离线单元测试（不访问网络）
```

## 运行测试

```bash
python -m unittest tests.test_mjpeg_reader -v
```

测试不访问真实网络，用 mock 替换拉流逻辑，直接喂 `android/v0-a4-stream-sample.mjpeg`
样本验证解析正确性。
